#+title: Yubikey Setup for Root CA
#+author: Root Keeper
#+date: 2026-05-25

* Overview

The Yubikey serves as a hardware security module (HSM)
for protecting the root CA private key. This guide
covers:
- Hardware requirements and selection
- PIV (Personal Identity Verification) setup and
  configuration
- Generating and importing keys
- Using Yubikey with OpenSSL for signing operations
- Security best practices and recovery procedures

The root CA private key **never leaves** the Yubikey;
all signing operations happen on the device itself.

* Yubikey Requirements

** Supported Models

| Model       | PIV | ECDP | Ed25519 | Recommended |
|-------------+-----+------+---------+-------------|
| YubiKey 5   | ✓   | ✓    | ✗       | ✓ RSA/ECDP  |
| Series      |     |      |         |             |
| YubiKey 5   | ✓   | ✓    | ✗       | ✓ FIPS      |
| FIPS Series |     |      |         | if required |
| YubiKey 5C  | ✓   | ✓    | ✗       | ✓ USB-C     |
| YubiKey 5   | ✓   | ✓    | ✗       | ✓ low-      |
| Nano        |     |      |         | profile     |
| YubiKey Bio | ✗   | ✗    | ✗       | ✗ biometric |
| Series      |     |      |         | only        |
| YubiKey NEO | ✓   | ✗    | ✗       | ⚠️ older,    |
|             |     |      |         | limited     |

**Recommendation**: YubiKey 5 Series (standard, USB-A)
or YubiKey 5C (USB-C)
- Firmware version 5.4 or later
- PIV applet enabled (default)
- FIPS version if compliance required

**Note on Ed25519**: YubiKey 5 series does NOT
currently support Ed25519 keys in PIV mode. For
modern Ed25519-based CAs, use RSA-4096 on Yubikey
with Ed25519 for intermediate CAs and end-entity
certificates.

** Hardware Considerations

- **Keep a backup Yubikey**: Store in secure
  location (safe, vault)
- **Physical security**: Prevent loss or theft
- **Environmental**: Avoid extreme heat/cold;
  keep dry
- **Lifespan**: 5-10 years typical; monitor for
  signs of failure
- **PIN attempts**: Limited (default 3 attempts
  before lockout)

* Initial Yubikey Setup

** Step 1: Reset the Yubikey (Clean Slate)

⚠️ WARNING: This deletes everything on Yubikey

#+begin_src bash
ykman piv reset
#+end_src

You'll be prompted to confirm. This resets:
- PIN to default: `123456`
- PUK to default: `12345678`
- Management key to default:
  `010203040506070801020304050607080102030405060708`

** Step 2: Set PIN, PUK, and Management Key

#+begin_src bash
# Change PIN (user authentication)
ykman piv access change-pin

# Change PUK (PIN unblock key, for resetting PIN)
ykman piv access change-puk

# Change Management Key (certificate management)
ykman piv access change-management-key
#+end_src

**Security Guidelines**:
- *PIN*: 6-8 digits, unique to this Yubikey
  - Example: `847392`
- *PUK*: 6-8 digits, different from PIN
  - Example: `293847`
- *Management Key*: Auto-generated by ykman
  (64-character hex) or custom
  - Let ykman generate it and save in
    encrypted password manager

Store these securely:
- PIN: Write down and store in safe (or
  password manager)
- PUK: Store in separate location from PIN
- Management Key: Store in encrypted password
  manager (e.g., `pass`)

Example using `pass`:
#+begin_src bash
pass insert ca/yubikey-pin
# Enter: 847392

pass insert ca/yubikey-puk
# Enter: 293847

pass insert ca/yubikey-management-key
# Enter: (copy from ykman output)
#+end_src

** Step 3: Verify Configuration

#+begin_src bash
# Check Yubikey status
ykman piv info

# Expected output:
# PIV version: 3.1.2
# PIN retries: 3
# Management Key Algorithm: TDES
#+end_src

* Generating Keys on Yubikey

The root CA key will be generated and stored on
the Yubikey. Never exported.

** Inspecting Your Yubikey Before Generating Keys

Before generating a new key, inspect what's already
on your device. This is essential if you're
experimenting or the Yubikey has been used before.

*** Full Device Overview

#+begin_src bash
ykman piv info
#+end_src

This shows:
- PIV version (e.g., 3.1.2)
- PIN retries remaining (default: 3)
- PUK retries remaining
- Management Key algorithm (TDES or AES)
- Slots and their status

Example output:
#+begin_src
PIV version: 3.1.2
PIN retries: 3
PUK retries: 3
Management Key Algorithm: TDES
PIN-protected: false
Touch policy for 9a: always
Touch policy for 9c: once
Touch policy for 9d: always
Touch policy for 9e: always
Chained certificates: false
#+end_src

*** Check Hardware and Firmware

#+begin_src bash
ykman info
#+end_src

Shows:
- Device name (YubiKey 5 NFC, etc.)
- Firmware version
- Serial number
- Enabled capabilities (OTP, FIDO, CCID, etc.)

Example:
#+begin_src
YubiKey 5 NFC (5.4.3) [OTP+FIDO+CCID]
Serial: 23027434
#+end_src

*** List All Keys on Device

#+begin_src bash
ykman piv keys list
#+end_src

Shows which slots contain keys:
- Slot 9a (PIV Authentication)
- Slot 9c (Digital Signature) ← **This is what we use**
- Slot 9d (Key Management)
- Slot 9e (Card Authentication)

Example:
#+begin_src
Slot 9c (Digital Signature):
  Type: RSA4096
  Subject: CN=Root CA,O=Organization
#+end_src

*** List All Certificates on Device

#+begin_src bash
ykman piv certificates list
#+end_src

Shows which slots have certificates installed.

*** Inspect Specific Slot (9c - Our Signing Slot)

Check if slot 9c already has a certificate:

#+begin_src bash
# Export certificate from slot 9c
ykman piv certificates export 9c -

# Or export and view human-readable format
ykman piv certificates export 9c cert.pem
openssl x509 -in cert.pem -text -noout
#+end_src

Output shows:
- Subject name
- Issuer
- Serial number
- Validity dates
- Public key details

*** Safety Check Before Generating

**⚠️ WARNING**: Generating a new key in slot 9c
**will overwrite any existing key permanently**.

Before proceeding, ask yourself:

1. **Is slot 9c empty?**
   #+begin_src bash
   ykman piv keys list | grep "Slot 9c"
   #+end_src
   If it shows nothing, slot 9c is empty and safe to use.

2. **If slot 9c is occupied, do you still have the key?**
   - If YES: You can use the existing key (don't generate
     a new one)
   - If NO: You'll lose access to it if you overwrite

3. **Is this your first time with this Yubikey?**
   - If YES: Run the inspection commands above first

*** Recovering an Existing Key

If slot 9c already has a key and you want to use it:

#+begin_src bash
# Export the certificate
ykman piv certificates export 9c root-ca.pem

# View details
openssl x509 -in root-ca.pem -text -noout

# Use this key for signing (no need to generate new)
# Proceed directly to signing operations
#+end_src

** Option A: Generate Key on Device (Recommended)

The key is generated directly on the Yubikey and
never leaves it:

#+begin_src bash
# Generate RSA-4096 key in slot 9c
# (standard for signing)
ykman piv keys generate --algorithm RSA4096 \
  --pin-policy once 9c

# Enter Management Key when prompted
# PIN policy 'once' means user must enter PIN
# once per session
#+end_src

**Slot Assignment** (PIV standard slots):
| Slot | Purpose | Our Use |
|------|---------|---------|
| 9a | Authentication | (not used) |
| 9c | Signature | ✓ Root CA signing key |
| 9d | Key Management | (not used) |
| 9e | Card Auth | (not used) |

*Why not Ed25519?* YubiKey 5 PIV mode doesn't
support Ed25519 in RSA-4096. Use this for root,
Ed25519 for intermediates.

** Option B: Generate Offline, Import to Yubikey

If you prefer to generate the key on the CA
machine, then import:

#+begin_src bash
# Generate RSA-4096 key offline
openssl genrsa -out /tmp/root-ca.key 4096

# Import to Yubikey (slot 9c)
ykman piv keys import 9c /tmp/root-ca.key

# Securely delete temporary key
shred -vfz -n 3 /tmp/root-ca.key
#+end_src

**⚠️ Risk**: Key exists on disk briefly. Only use
this if you must generate offline.

** Step 4: Create Self-Signed Root Certificate

Now create the root CA certificate using the
Yubikey key:

#+begin_src bash
# Generate certificate signing request
# (uses Yubikey key)
ykman piv certificates request 9c root-ca.csr \
  --subject "C=SE,ST=Stockholm,O=Organization,CN=Root CA"

# Self-sign the CSR (using Yubikey to sign itself)
openssl x509 -req -days 7300 -in root-ca.csr \
  -signkey /path/to/key \
  -out root-ca.crt
#+end_src

**Better approach** using OpenSC and PKCS#11:

#+begin_src bash
# Export the public key from Yubikey
ykman piv certificates export 9c root-ca.pub

# Use Yubikey directly for signing (via PKCS#11)
# See "Using Yubikey with OpenSSL" section below
#+end_src

* Using Yubikey with OpenSSL

OpenSSL can interact with Yubikey via PKCS#11
(smart card standard).

** Prerequisites: OpenSC PKCS#11 Module

Verify OpenSC is installed and locate the
PKCS#11 library:

#+begin_src bash
# Linux
find /usr/lib -name "libopensc.so*" 2>/dev/null

# macOS
find /usr/local/lib -name "libopensc*" 2>/dev/null

# Windows
C:\Program Files\OpenSC Project\OpenSC\bin\opensc-pkcs11.dll
#+end_src

** Method 1: Using OpenSC's OpenSSL Plugin

#+begin_src bash
# Set environment variable for PKCS#11 engine
export OPENSC_PKCS11=/usr/lib/x86_64-linux-gnu/libopensc.so

# List available keys/certificates on Yubikey
openssl engine pkcs11 -pre SO_PATH:$OPENSC_PKCS11

# List objects
openssl engine dynamic -pre SO_PATH:/usr/lib/x86_64-linux-gnu/libopensc.so \
  -pre ID:pkcs11 -pre LIST_OBJECTS
#+end_src

** Method 2: Using yubico-piv-tool (Recommended)

The `yubico-piv-tool` makes Yubikey operations
simpler:

#+begin_src bash
# List certificates and keys on device
yubico-piv-tool -a list

# Export public key
yubico-piv-tool -a read-cert -s 9c \
  -o root-ca.pub.pem

# Sign a CSR using Yubikey key
yubico-piv-tool -a sign-csr -s 9c \
  -i intermediate-ca.csr \
  -o intermediate-ca.crt \
  --pin <PIN>
#+end_src

** Method 3: Direct OpenSSL with PKCS#11 (Advanced)

For advanced usage, configure OpenSSL to use
Yubikey directly:

Edit `~/.openssl/openssl.cnf` or create CA-specific
config:

#+begin_src conf
engines = engine_section

[engine_section]
pkcs11 = pkcs11_section

[pkcs11_section]
engine_id = pkcs11
dynamic_path = /usr/lib/x86_64-linux-gnu/engines-1.1/pkcs11.so
MODULE_PATH = /usr/lib/x86_64-linux-gnu/libopensc.so
PIN = 123456
#+end_src

Usage:
#+begin_src bash
# Sign CSR using engine
openssl ca -engine pkcs11 -config openssl.cnf \
  -in intermediate-ca.csr -out intermediate-ca.crt
#+end_src

* Daily Operations with Yubikey

** Before Each Session

1. Insert Yubikey into USB port
2. Verify it's recognized:
   #+begin_src bash
   ykman list
   #+end_src
3. Authenticate to the device:
   #+begin_src bash
   ykman piv info
   # Enter PIN when prompted
   #+end_src

** Signing Certificates

To sign an intermediate CA CSR with the Yubikey:

#+begin_src bash
# Verify CSR format
openssl req -in intermediate-ca.csr -text \
  -noout -verify

# Use yubico-piv-tool for signing
yubico-piv-tool -a sign-csr -s 9c \
  -i intermediate-ca.csr \
  -o intermediate-ca.crt \
  --pin $(pass show ca/yubikey-pin)

# Verify signed certificate
openssl x509 -in intermediate-ca.crt -text -noout
#+end_src

** Locking / Unlocking

If PIN is entered incorrectly 3 times, the Yubikey
locks:

#+begin_src bash
# Check PIN retries
ykman piv info

# If locked (0 retries), unblock with PUK
ykman piv access unblock-pin
# Enter PUK when prompted
# Then set new PIN
#+end_src

** Removing Yubikey

When done with a session:

#+begin_src bash
# Logout from Yubikey (optional, but good practice)
ykman piv access logout

# Remove from USB port
# (Yubikey does not need to be "ejected"
# like a disk)
#+end_src

* Security Best Practices

** Physical Security

1. **Possession**: Keep Yubikey on your person
   or in secure location
2. **Backup**: Create a second Yubikey with
   identical keys/certs, store offline
3. **Inspect**: Check for signs of tampering
   before each use
4. **Storage**: Use a small case or Faraday bag
   (optional)

** PIN & PUK Management

| Item | Storage | Access | Review |
|------|---------|--------|--------|
| PIN | Password | Root | Monthly |
| | manager | keeper | |
| | (encrypted) | only | |
| PUK | Separate | Root | Yearly |
| | location | keeper | |
| | (safe) | only | |
| Mgmt Key | Password | Root | Monthly |
| | manager | keeper | |
| | | only | |

**Rotation Schedule**:
- PIN: Change annually or when personnel
  changes
- PUK: Change every 2 years
- Management Key: Change every 2 years

** Compromise Procedures

If PIN is compromised:
#+begin_src bash
# Immediately change PIN
ykman piv access change-pin

# Alert team; review signing logs for
# unauthorized activity
#+end_src

If Yubikey is lost/stolen:
1. **Immediately**: Revoke all certificates
   signed by this Yubikey
2. **Report**: Document incident and notify
   stakeholders
3. **Generate new key**: Create new Yubikey
   with new key/cert
4. **Update trust**: Have intermediate CA
   issue new cert from new root

If root CA private key is compromised:
1. **Emergency**: Revoke all issued
   certificates (full CRL)
2. **New root**: Generate completely new root CA
3. **Transition**: Notify all stakeholders;
   announce deprecation date for old root
4. **Infrastructure**: Update clients to trust
   new root CA

* Backup & Recovery

** Creating Backup Yubikey

To protect against loss or failure of the
primary Yubikey:

#+begin_src bash
# Step 1: Export certificate and public key
# from primary
ykman piv certificates export 9c root-ca.pub.pem
ykman piv certificates export 9c root-ca.crt

# Step 2: On backup Yubikey, generate
# identical key
ykman piv reset  # On backup device
ykman piv keys generate --algorithm RSA4096 9c

# Step 3: Install the same certificate
ykman piv certificates import 9c root-ca.crt
#+end_src

**Note**: The backup Yubikey will have a
*different private key*. You must:
- Have the *same certificate* installed
- Use alternative approach: Export/import
  private key (risky) OR
- Have new root sign the backup Yubikey's key
  (recommended)

**Better approach** (recommended):
1. During initial setup, prepare TWO Yubikeys
   with identical private keys
2. Generate key once, export temporarily,
   import to both
3. Destroy temporary key files
4. Store one Yubikey offline as backup

** Recovery if Primary Yubikey Fails

If primary Yubikey dies:

#+begin_src bash
# Step 1: Retrieve backup Yubikey from
# secure storage
# Step 2: Verify it has the root CA key
ykman piv info
ykman piv certificates export 9c root-ca.pub.pem

# Step 3: Resume normal operations using backup
# (Same PIN/PUK/Mgmt Key as primary)

# Step 4: Maintain the backup Yubikey as
# primary going forward
#+end_src

* Testing & Verification

** Verify Yubikey is Working

#+begin_src bash
# Check device info
ykman piv info

# List all certificates/keys
ykman piv certificates list

# Export public key
ykman piv certificates export 9c root-ca.pub.pem

# Verify public key format
openssl x509 -in root-ca.pub.pem -text -noout
#+end_src

** Test Signing Operation

Before using in production, test that signing
works:

#+begin_src bash
# Create a test CSR
openssl req -new -key /tmp/test.key \
  -out /tmp/test.csr \
  -subj "/CN=test.example.org"

# Sign it with Yubikey
yubico-piv-tool -a sign-csr -s 9c \
  -i /tmp/test.csr -o /tmp/test.crt \
  --pin $(pass show ca/yubikey-pin)

# Verify signature
openssl x509 -in /tmp/test.crt -text -noout

# Cleanup
rm /tmp/test.*
#+end_src

** Verify PIN/PUK/Mgmt Key

#+begin_src bash
# Test PIN
ykman piv info
# Enter PIN when prompted; should succeed

# Test PUK (only if needed to unblock PIN)
# Lock PIN first (intentionally enter wrong
# PIN 3 times)
# Then: ykman piv access unblock-pin
# Enter PUK when prompted

# Test Management Key
ykman piv access change-management-key
# Enter current management key when prompted
# Press Ctrl+C to cancel (don't actually
# change it)
#+end_src

* Troubleshooting

** Problem: Yubikey Not Recognized

#+begin_src bash
# Check USB connection
lsusb | grep -i yubico

# Restart smart card daemon
sudo systemctl restart pcscd

# Reinstall drivers (Windows)
# Unplug Yubikey, uninstall in Device
# Manager, reconnect
#+end_src

** Problem: PIN Locked (3 failed attempts)

#+begin_src bash
ykman piv info
# Output shows: PIN retries: 0

# Unblock with PUK
ykman piv access unblock-pin
# Enter PUK when prompted
# Set new PIN
#+end_src

** Problem: "ykman: error: No device to load"

#+begin_src bash
# Check if ykman sees the device
ykman list --serials

# Try resetting USB connection
sudo systemctl restart pcscd

# On Linux, may need to add udev rules
sudo curl https://raw.githubusercontent.com/Yubico/yubikey-manager/master/linux_install/70-u2f.rules | sudo tee /etc/udev/rules.d/70-yubico.rules
sudo udevadm control --reload
#+end_src

** Problem: OpenSSL Can't Access Yubikey

#+begin_src bash
# Verify PKCS#11 module is available
find /usr/lib -name "libopensc.so*"

# Test with pkcs11-tool
pkcs11-tool --module \
  /usr/lib/x86_64-linux-gnu/libopensc.so \
  --list-objects

# Verify engine is installed
openssl engine -t
#+end_src

** Problem: Certificate Verification Fails

#+begin_src bash
# Check certificate details
openssl x509 -in root-ca.crt -text -noout

# Verify signature
openssl x509 -in root-ca.crt -text -noout | \
  grep -A 3 "Subject:"
openssl x509 -in root-ca.crt -text -noout | \
  grep -A 3 "Issuer:"

# If self-signed, Issuer should equal Subject
#+end_src
